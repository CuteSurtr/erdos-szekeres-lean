## Method
`close_march.py` here is a copy of `results/Mii-S/scripts/close_march.py`, changed as follows:
- `--top`, `--shard` and `--nshards`: I processed only the top cubes at 0-based line index
  i ≡ 11 (mod 12), which are lines 11, 23, …, 119.
- A leaf counts as closed only when cake_lpr prints `s VERIFIED UNSAT`.
- SPLIT records store their children, so a restart replays the tree. `--summarize` rebuilds
  `leaves.icnf` and `open.icnf`.

Parameters: CaDiCaL `--lrat -t 300`; a cube that times out is split with `march_cu -d 6`; 4 jobs.

Incident: at the first push, the `git pull --rebase --autostash` replaced `leaves.jsonl` while
the run was still writing it. The run kept writing to the deleted inode. I copied the complete
log from `/proc/<pid>/fd` and restarted from it with the same script, now running in a directory
outside the repo. Each commit copies the files into the repo. No records were lost. The work in
flight at the restart (≤4 cubes) was redone.

The run was stopped at 10:32 UTC to stay inside the time budget. Cubes in flight at that moment
have no record, and they are in `open.icnf`.
