## Findings (all minor)

### m1 (minor): the map note for `mm:thm:odd` contradicts the section's own indexing
- **Location:** `sections/mm.map.tsv`, line 15 (row `mm:thm:odd`), note column.
- **Issue:** the note says "Lean j = text j minus 1". This section states Theorem `mm:thm:odd` with the Lean j:
  k = 2j+1, (j+1)-caps, `sections/mm.tex:582-590`. Remark (3) at lines 660-663 correctly says that the Lean j is
  j'-1 for the j' of the *written sources* (README/PROOFS). If the map notes are printed in the appendix map, a reader
  will take "text" to mean this document, and then the note is false.
- **Fix:** "Lean j = README/PROOFS j minus 1; this section uses the Lean j."

### m2 (minor): unsupported provenance claim "the remaining lines are written by hand"
- **Location:** `sections/mm.tex:39-42`.
- **Issue:** the record supports only part of this.
  - The file header (`MIRRORETV/lean/MirrorMain.lean:4-10`) says that `MirrorPolygons.lean` and `small_polygons.lean`
    were generated by `gen_lean.py`, with certificates from `gen_certs.py`.
  - The header lists the other assembled files without saying how they were produced. Nothing in the unit or the
    README says they were written by hand.
- **Fix:** "the remaining lines were not produced by that generator". I checked that the generator is indeed absent.
  The only `gen_lean.py` in the repository is `C2FINAL/gen_lean.py`, an unrelated Central34 data writer.

### m3 (minor): Theorem `mm:thm:axis-polygon`(b), Claim 2: "the other cases are separated by the abscissae"
- **Location:** `sections/mm.tex:389-390`.
- **Issue:** the text treats r < m <= s, then says "the other cases are separated by the abscissae". It does not say
  "w.l.o.g. r < s", so the other cases include s < m <= r, and that case is not separated by abscissae. Example:
  s = 0 and r = 2m-2 give q_s = mir c_0 and q_r = c_0, which have the same abscissa. That case is separated by the
  ordinates, symmetrically to r < m <= s. The proof of Theorem `mm:thm:mirror-polygon` (line 299) handles this
  correctly ("the case s<m<=r is symmetric"). Part (a), at lines 361-363, also leaves the symmetric case implicit.
- **Fix:** add "(the case s<m<=r is symmetric)" in (a) and (b).

### m4 (minor): name clash in the parenthetical of Theorem `mm:thm:small`(b)
- **Location:** `sections/mm.tex:836-840`.
- **Issue:** "Proposition (f) with a = c_0 when c_0 lies on the axis" uses c_0 for the cap point, but the Proposition
  has its own c_0, c_1. The Lean call is `axis_left_pentagon (c 0) (c 1) (c 2)` (`MirrorMain.lean:2088`), which binds
  the Proposition's a, c_0, c_1 to the cap's c_0, c_1, c_2. Likewise, (g) binds the Proposition's (a, c_0, c_1) to
  the cap's (c_2, c_0, c_1) (`MirrorMain.lean:2076`). The (b) item is fine. Only the (f) reading needs care.
- **Fix:** spell out the substitution, e.g. "(f) with (a, c_0, c_1) := (c_0, c_1, c_2)".

### m7 (minor): Definition `mm:def:config`(c) restricts `xset` and refers forward
- **Location:** `sections/mm.tex:137-143`.

## Attack log: why each main statement survives

**Fidelity sweep.** I compared every Lean head in the scope with the text: argument order, strict vs weak inequalities,
`Fin` index side conditions, `HasConvexNGon (2 * m - 1)` with m >= 3, `K - 1` with K >= 4, `Finset` images, and
maps-into symmetry. All match.
- Configuration and HasCap (`Realization.lean:9, 64`) are the all-triples notions stated in Definition
  `mm:def:config`.
- hM in `mirror_odd_general` / `mirror_even_general` (`MirrorMain.lean:2498, 2599`) is stated exactly, with quantifier
  order `∀ n (c : Configuration n), ¬HasCap → ¬HasConvexNGon → n ≤ M`. M is an assumed bound and is stated as such,
  with the Lean j.

**Lemma `mm:lem:slope`(a) (`cap_below_lines`).** I re-derived all five positions of l (l<i, l=i, i<l<j, l=j, l>j).
The identity (e) and the i<l<j expansion -(x_j-x_i)y_l - y_i(x_j-x_l) - y_j(x_l-x_i) were verified with sympy. The
lemma needs y >= 0 only at i and j (i<l<j case) and y_l > 0, exactly as in Lean. For m = 0, 1 the statement is
vacuous. No hidden hypothesis.

**Theorem `mm:thm:mirror-polygon` (`cap_mirror_polygon`).**
- The split t<m / s<m<=t / r<m<=s / m<=r is exhaustive.
- In each case the identity is applied with the right arguments:
  - Case 2: (c) of `orient-mir`, then slope (a) with (r, s, u).
  - Case 3: cyclic, then swap12, then slope (a) with (u, u', r), where u < u' because s < t.
  - Case 4: reverse, then the cap hypothesis with d < b < a.
- For m <= r <= 2m-1, the map r -> 2m-1-r lands in [m].
- Injectivity: same chain by abscissae; different chains by the sign of y.
- m = 2, the smallest allowed case, worked by hand: all 4 triples are covered by Cases 2 and 3, via the l=i or l=j
  branch of slope (a).
- Numeric: 400 random exact-rational caps (m = 2..7). The text's list q is injective and every one of its C(2m,3)
  increasing triples is positive. 0 failures.

**Theorem `mm:thm:axis-polygon` (`axis_left_polygon`, `axis_right_polygon`).**
- The special Case 3a uses the cap hypothesis directly:
  - (a): orient(c_0, c_u', c_u) = -orient(c_0, c_u, c_u') with 0 < u < u'.
  - (b): the reverse identity with u < u' < m-1.
  This matches Lean, and is necessary because slope (a) needs y_l > 0 and y = 0 at the axis point.
- Case 2 with r or s equal to the axis index is still covered by slope (a), because only y_u > 0 is needed and u is
  in {1..m-1}, resp. {0..m-2}.
- Truncated subtraction: 2m-1-r >= 1 for r <= 2m-2, and 2m-2-r <= m-2 for r >= m. m >= 3 gives 2m-1 >= 5 >= 4 for
  the positive-cycle lemma.
- Numeric tests of both lists: 0 failures.

**Proposition `mm:prop:small-polygons` and Lemma `mm:lem:cyc`.**
- All nine generated heads (`MirrorMain.lean:212, 392, 639, 816, 1126, 1168, 1282, 1358, 1433`) match items (a)-(i):

**Lemmas `mm:lem:count`, `mm:lem:injx`, `mm:lem:sort`, `mm:lem:ngon` and `mm:lem:upper-caps`.**
