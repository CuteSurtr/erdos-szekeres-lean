Why 149 of the 192 chain .olean files differ from the October records (5 November 2026, 23:2x UTC; second case added 6 November)

The modules whose .olean differs are exactly those that the October checkers compiled without --root:
scripts/check_omission_geometry.py, check_omission_residual_geometry.py and check_omission_residual_blocks.py
run  lean -j 1 -s 32768 -M <mem> <source> -o <obj>  with cwd = the repository root, so Lean derives the main
module name from the path relative to the cwd (e.g. «.cache».«omission-balanced-rows-only».Geometry00000),
not "Geometry00000". build_chain311.py compiles every module with -R build/chain311/src, under its import name.

Test (one module, Lean 4.24.0, under MemoryMax=12G, MemorySwapMax=0):
  cd build/chain311/modname-test   (holds .cache/omission-balanced-rows-only/Geometry00000.lean, the pinned source)
  LEAN_PATH=<lake LEAN_PATH>:build/chain311/olean lean -j1 -s 32768 \
    .cache/omission-balanced-rows-only/Geometry00000.lean -o Geometry00000.noroot.olean

So with the October module name the build reproduces the October object byte for byte.

module name; the replay command documented in omission-residual-geometry-2026-10-09/README.md compiles it under
another module name and does not reproduce the October object.

The other 147 differing modules (83 Geometry*, BalancedRows, ResidualCycleIndex, ResidualGeometry*,
ResidualGeometry, ResidualBlock*, ResidualAllGeometry) were not recompiled this way; the same cause is likely
but not checked module by module (ResidualCycleIndex and the residual geometry also import Catalog, so a
different Catalog object changes their bytes too). The 43 modules that the October records compiled with
--root (the 11 October bridge record's fresh modules, BalancedProof.Catalog, BalancedCoverCutsV2) are
byte-identical as built here.
