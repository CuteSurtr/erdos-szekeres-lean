## 4. Step 4 in detail

### 4.1 Own definitions (from parent README §2, §6.1–6.2, §6.7 and math.md §2.3)

- States: the 70 profiles 4 ≥ f₁ ≥ f₂ ≥ f₃ ≥ f₄ ≥ 0, ordered by (sum, profile); cells (a, y), a = cap coordinate.
  capH = number of nonempty columns, cupH = f₁. D(s→t) = I(t) \ I(s); refined D′(s→t) = {(a,b) ∈ D : a ≤ capH(s)+1,
  b ≤ cupH(s)+1}; can(s,t) = D′(s→t) ≠ ∅.
- Six-order test TT[a,b,c]: for each of the six chronological orders (p,q,r) of {a,b,c} whose three directed domains
  are nonempty, an even order needs max cap-coordinate of D(q→r) ≤ min cap-coordinate of D(p→q) (no cap growth, so a
  cup), an odd order the same with the cup coordinate. Own table (C++ and, separately, Python): **29,436 forced ordered
  triples**, no triple with both orientations forced, invariant under cyclic shifts; equal to the count in parent
  README §2.6. The table built from the refined domains is the same set.
- τ = transposition of the cell set (conjugate partition): 16 fixed states, 27 nontrivial orbits.
- Numbering (the documented layout, reproduced): per pair i < j in lexicographic order 7 variables (before, cap_ge
  2..4, cup_ge 2..4); orientation per sorted triple from 16,906; convex_four per sorted quadruple up to 988,540;
  sel_s = 988,541 + s; then C₃,U₃,C₄,U₄,C₅,U₅ for every ordered triple (a,b,c), in lexicographic order, with
  can(a,b), can(b,c), can(a,c); then CE(p,q), UE(p,q) at the first (p,u,q) with C₅; then the counter; then the SB
  auxiliaries.

### 4.5 Rows

A row clause ∨_{s∈T} ¬sel_s claims that no set of the class occupies all of T. For each row clause of each cube, the
justification that the cube's `tcert/justification.json` claims for T is checked with own code (`rowchk.py`):

- **cycle**: the order is a permutation of T with 8 states (demand 1 = 8 − 7), and every triple in list order passes
  the own TT (math.md Lemma 2.2);
- **mirror**: the preimage's support mapped by the own τ is T (mirror lemma, parent README §2.8), and the preimage is
  checked by its own kind;
- **transported**: σ is a bijection from the template's core indices onto T, and every kept test of the template holds
  for σ's states with the own D′ and TT (a domain test also when D′ is empty: the empty unit implies it). The template
  CNF is then **regenerated by the own coupled-CNF generator `cnfgen`** (static families of parent README §2.7 for n
  owners: threshold monotonicity, transitivity, growth with ceilings, signotope packets, convex_four definition,
  no-octagon for the listed 8-subsets or all of them, plus the kept test clauses) and **re-certified** here: CaDiCaL
  2.1.3 `--lrat=true --binary=false`, exit 20, cake_lpr `--CML_HEAP_SIZE=2000` with the exact line `s VERIFIED UNSAT`.
  By transport (§2.9), CNF(σ) contains every clause of this CNF, so it is UNSAT too;
- **core**: the support's own full coupled CNF (complete no-octagon family), or for a recorded big core the static part
  + the recorded octagon list + all state-dependent clauses, regenerated by `cnfgen` and re-certified the same way.

Own generator `cnfgen`: own numbering, every test checked to hold for the given state list before writing. Its convex
position rule (exactly two of χ(abc), −χ(abd), χ(acd), −χ(bcd) positive) is an own derivation. **Positive control:**
`cnfgen --control 5 1500`: 1,500 random real sets in the class (5–13 points, exact integers; 2,244 sets in general
position tried, 68 of the 70 states seen as owners, owners in a random index order), the canonical assignment, the
complete coupled CNF (all static families, complete no-octagon, all state-dependent clauses): **42,454,218 clause
evaluations, 0 violations**; the convex rule agreed with the geometric test on 172,506 / 172,506 quadruples.

### 4.6 What step 4 does not show

- The soundness of each family is the record's written argument (parent README §2.7–2.9, §6.3, §6.7); step 4 shows that
  every used clause is an instance of those families as defined. The own positive controls above test the generators
  on real sets; they are not proofs. (Reviewer's note, not a new proof: the arguments of §6.3 for F1–F8, of §2.7 for the
  coupled families, the transport argument of §2.9, the mirror lemma §2.8 and the LEX argument §6.7 were read and found
  correct as written; in particular F1 positive uses the plain-domain six-order test, which is valid because every
  actual x-order of three owners has nonempty directed domains, and F7's exclusion needs only that the cap's inner
  points lie above and the cup's below the common chord.)

  taken from the documented layout and from reading the record's generator code (coupled5.py, mono66.py, lazymono.py);
  the family logic was written from the README definitions. A conceptual error shared with the record's definitions
  would not be caught by step 4 itself; the controls on real sets are the check against that.
- The tie between a row and its template rests on the transport argument (parent README §2.9); the tests are checked
